# 手動v5：拘束判定の補完と二人目の受付

過去版の記録。現行版は[手動v6](manual-v6-validation.md)。

対象は提供されたUS 1.00 DOL、Dolphin 5.0-21460。
ユーザーの対戦条件は全員Human・チーム戦ON、1P・2Pと両手は別チーム。
CPU用v4の通常版・確認版はバイト列を変更していない。

## 変更

`patches/manual_grab.s` を手動版だけに組み込み、両手のTagGrabアニメーション
コールバックから実行する。46〜73フレームで判定がなければ、ゲーム本体の
判定生成関数 `0x800710A8` に従来と同じ骨18・半径24のCatch命令を渡す。
保持枠に空きがある間は掴み受付フラグも設定する。74フレーム以降、または二人を
保持した後は判定と受付を閉じる。元の音声命令は維持する。

ゲーム本体の候補走査 `0x80078758` は、重なった全候補を命中履歴へ記録するが、
実際の拘束対象は一人だけ選ぶ。実DOLの処理で、最初の走査に相手二人を重ねると
二人とも履歴に入り、一人目の拘束後にもう一度走査しても二人目が除外されることを再現した。
v5では空き枠がある間、`0x80008440` でCatchの履歴を更新する。
既に拘束した相手はネイティブの拘束マスク `0x1ff` で除外される。

対象選択と拘束はゲーム本体の処理を使用する。距離だけで強制拘束したり、
味方・無敵の条件を無視して相手の所有者ポインタを書き込む処理は追加していない。
二人は連続する二回の走査で拘束され、その後は既存の二人保持・同時ダメージ・投げ処理へ進む。

## 検証

提供DOLをUnicornへ読み込んで以下を実行した。

- 実際の判定デコーダ、Catch対HurtCapsuleの重なり計算 `0x80007ECC / 0x80006E58`。
- 全員Humanのスロット設定、チーム戦ON、味方攻撃OFF。
- 同じ手側に重なる相手二人について、MH・CHそれぞれの拘束コールバックが両者を拘束。
- 初回走査の履歴が二人目を除外する旧動作と、履歴更新後に二人目も拘束する動作。
- スクリプトを実行せず判定・受付フラグが欠けた条件でも、52フレームから補完して拘束。
- 空中の相手への拘束、味方・無敵・遠距離の相手の除外、74フレームでの判定終了。
- 手動版の両手のアニメーションコールバックから判定が生成されること。
- 既存の五回の握りダメージ・命中音・二人への投げが手動版でも維持されること。

既存項目を含め49項目成功。追加テストは `tests/test_native_grab.py`。
ネイティブ判定テストではアニメーション後のワールド座標を固定値で与え、
モデル描画・ステージ遮蔽・アニメーション読み込み・拘束のジョイント接続等を代替している。
Unicornが対応しないpaired-single行列積も同等のスカラー計算へ置き換えている。
拘束対象の選択、チーム・無敵・マスクによる除外、球とカプセルの重なりは実DOLの命令を実行する。

「手動時に一人も捕まらない」という報告そのものはDolphin上で再現できておらず、
その原因を断定した修正ではない。判定生成の補完と、再現できた二人目の受付不具合を修正した版。
Dolphinでの入力から拘束・投げまでの実動作、および参考映像との完全一致は未検証。
