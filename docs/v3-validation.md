# v3：片手での2人拘束と叩きつけ

US 1.00 / Dolphin 5.0-21460向け。2026年11月22日更新。

## 変更

- MHとCHにそれぞれ2人分の保持枠を用意。最初の1人では掴み受付を閉じない。
- 本来1人分の `victim_gobj` が次の探索で上書きされても、保持枠から拘束を維持する。
- 被拘束者ごとの攻撃判定開始時に、捕獲元の現在の対象をその被拘束者へ切り替える。
  同じ手の握り判定から、保持している2人の両方へダメージを与える構成。
- 投げと中断時の解放は2枠を走査。同じ相手の拘束を別の手が奪わない。
- 解放位置は手のbone18から12単位下。手のモデル倍率を反映し、衝突履歴の座標も更新する。
- 投げ角度を両手とも270度へ変更。床への接触後に衝撃演出を呼び、90度で跳ね返す。
  跳ね返りでダメージを重複加算せず、その後の衝突処理は通常状態へ戻す。

同じ手に2人とも掴まれた場合、その手のダメージを各人に適用する。
MHは各人6×5＋12＝42%、CHは各人7×5＋16＝51%と花の継続ダメージ。

## 検証

提供DOL・DAT・AJの照合後に生成。32項目のテストが成功した。
MHだけで2人、CHだけで2人を保持するケースについて、各人5回の握りダメージ、
同じ更新内の2人分の投げ、手の下への配置、下向き解放、床接触前は跳ね返らず接触後に
上向きへ切り替わる処理、投げダメージを再加算しないこと、死亡時の2人解放を検証した。

コマンドのデコーダには提供DOLの命令を使用した。ゲーム全体を実行したものではなく、
モデルテストの床接触・骨の座標・衝突する相手はテスト側で与えている。
**Dolphin上でのv3の衝突・描画・音声出力と、参考動画との完全一致は未確認。**

## 配布とメモリ

通常版3048バイト、確認版3024バイト。既定Gecko容量3256バイト以内。
初回発動時にゲーム内ヒープへ3344バイトを確保し、生成したコード本体を展開する。
データ・命令キャッシュを更新してから実行し、次のヒープ再作成前に参照を無効化する。
展開結果、同一ヒープでの再利用、ヒープ再作成後の再確保・再展開も命令実行で確認した。

旧版は無効にし、ステートセーブを読み込まずタイトルから起動する。
コード本体・ビルダー・テストを同梱し、ゲームのバイナリや映像は同梱しない。
