# 提供されたUS版1.00実行ファイルの静的解析

これは実行ファイル受領時の調査記録です。その後のDAT・動画との照合および試験用コードは
[復元の実装記録](restoration.md)を参照してください。

## 入力と確認範囲

- ユーザー指定の環境：US版1.00、Dolphin 5.0-21460。
- ユーザー指定の[参考動画](https://www.youtube.com/watch?v=do8EdYx5OaE)。
  この環境ではYouTubeへの取得要求が拒否されたため、再生内容・説明文は未確認。
- 提供された `main.dol`：4,417,056 bytes。
- SHA-256：`2f4e499c05943c64a89a2978488456a9d88582a0b662eb1ec9878eb0a94c479b`。
- ビルド文字列：`DATE Oct 31 2001  TIME 04:35:57`。

これは提供ファイルの識別情報である。US地域はユーザー申告であり、
ビルド日時だけでディスクの地域や未改造であることを確定してはいない。
以下はこのSHA-256のファイルだけを対象にしたアドレス。
エミュレータ上の実行検証はまだ行っていない。

## 実行ファイルから確認した箇所

| 処理 | メモリアドレス |
| --- | --- |
| マスターハンド待機中の行動選択 | `0x8014F8E0` |
| クレイジーハンド待機中の行動選択 | `0x80155A84` |
| マスターハンドの4番目の連携分岐 | `0x8014FB18` |
| クレイジーハンドの4番目の連携分岐 | `0x80155FC8` |
| マスターハンドの行動表 | `0x803D2218` |
| クレイジーハンドの行動表 | `0x803D29C0` |

4番目の分岐はいずれも、座標をスタックに保存した後、そのまま処理末尾へ分岐する。
移動・開始コールバックの登録が欠けていることを逆アセンブルで確認した。
クレイジーハンドの連携候補グループも `0F 03`（開始インデックス15、候補数3）であり、
行動表には4番目の候補が登録されていない。
これは1.02の公開ソースで見つけた構造と一致する。

ただし、これだけでは掴み技の復元にはならない。技の開始時に両手を連携させ、
掴まれた相手の参照と成功・失敗・中断時の処理を正しく設定する必要がある。

## アクションとモーションの番号

実行ファイルのアクション表は、マスターハンドが `0x803D1B78`、
クレイジーハンドが `0x803D2340`。各行は32 bytes。
どちらも action ID 341の先頭行で motion ID 295を使用している。

公開ソースにはクレイジーハンドのアクション名にマスターハンドの列挙子を流用している
箇所がある。例えば同じ数値385でも、両手で同じ技とは限らない。
掴み復元コードの作成前に、キャラクターのDAT側の技名・サブアクションと照合する。
名前だけを根拠に385を両手へ設定する方法は採用しない。

`tools/inspect_dol.py` は、対象ファイルのハッシュ、主要箇所のバイト列、
アクション表のmotion IDとアニメーションコールバックを照合・表示する。
アドレスを1.02から一律の差分で換算する方法は使用していない。

## 通常乱闘のHuman連携入力経路（US版1.00で確認）
提供された同じSHA-256の `main.dol` をPowerPC逆アセンブルして確認した。

- クレイジーハンドのHuman入力は `0x801565B4` で `li r0,380` を実行し、`0x801565CC` で `0x2250` へ格納する。
- クレイジーハンドの到着コールバック `0x8015A114` はモーション384へ変更する。
- マスターハンドのHuman入力関数は `0x8015BB10` から相方の要求値を読み、`0x80150250` 以降で比較する。
- 要求値380は `0x80150270` の比較を通過し、4番目の欠けた連携分岐 `0x8015030C` へ分岐する。その末尾 `0x80150320` の命令は `stfs f0,0x18(r1)`。
- `Player_GetEntity` は `0x80034090`。Human手の取得にはP3=slot 2、P4=slot 3を使う。

したがって、US版1.00のHuman連携開始条件は380である。383は別バージョンのenumから持ち込んだ誤った値であり、今回の修正では使わない。上記の7箇所を `config/us-1.00.json` のバイト照合にも追加した。

## 次に必要なデータ

同じゲームディスクから抽出した `PlMh.dat` と `PlCh.dat`。
これらにある技の設定・サブアクションを読み、未使用技の番号と掴み判定を確認する。
`main.dol` のみでは、DAT内の掴み判定の有無やモーションとの対応を確認できない。

完成の確認条件は、CPUによる選択、両手の同期、掴み成功、空振り、片手が倒れた場合の中断、
終了後の通常行動への復帰。現段階の成果は静的解析と照合ツールであり、実行用コードではない。
