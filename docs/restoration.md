提供された動画ファイルは約9.8秒。両手が別々のキャラクターを拘束し、
握り5回の後に投げる場面を確認した。
マスターハンド側は6%ずつ計30%、投げを含め42%になる。
クレイジーハンド側は最初の握りで7%になり、その後に1%ずつの継続ダメージも表示される。
これは通常掴みデータにも残るLipstick属性（花）と整合する。

復元の設定値はMH「6×5＋12」、CH「7×5＋16＋花」。
CHの直接ダメージは51%であり、継続ダメージを含む最終表示は経過時間にも依存する。
単に各握りを8%に設定したり、最終表示を58%に固定したりする実装にはしていない。

## 名前とアクションの対応

| 技名 | MH motion / action | CH motion / action |
| --- | --- | --- |
| Tagtsukamu | 339 / 385 | 334 / 380 |
| Tagnigiru | 340 / 386 | 335 / 381 |
| Tagshippai | 341 / 387 | 336 / 382 |
| Tagcancel | 342 / 388 | 337 / 383 |

上記はDAT内の名前と、提供されたDOLのアクション表を直接対応させたもの。
CHのaction385・386は死亡モーションであり、MHと同じ番号で開始してはいけない。

MHのTagtsukamuには46フレーム目からの掴み用判定が残る。
CHのTagtsukamuにはタイマーと判定消去しかなく、Tagnigiruにも握りの判定がない。
そのため、選択分岐への呼び出し追加だけでは完成しない。

## 現行v4の実装

Gecko C2フックは5箇所。従来の連携選択・CHの未使用分岐・MHの未使用分岐に加え、
キャラクター音声の読み込み要求とゲーム内ヒープの再作成処理を補う。

ゲーム本来の各手の `victim_gobj` は1人分しかなく、次の掴み探索でも上書きされる。
v3では各手に2人分の保持枠をペイロード内に用意し、相手側の捕獲元との相互関係を検証する。
最初の1人では掴み受付を閉じず、2人目の成功後に閉じる。
v4では握りの各回に保持枠を走査し、相手側の捕獲元がその手であることを確認してから
ゲーム内のダメージ加算関数を呼ぶ。見えない被拘束者と手の空間判定の重なりには依存しない。
CHはUS 1.00の整数引数の花付与関数を呼び、継続ダメージをゲーム側に任せる。

段階と握り・投げのイベントはMHが一括管理する。両手が掴みモーションを終えてから次へ進む。
握りを適用しても保持枠を消さず、投げ・中断時の解放で初めて枠を消す。
ダメージの記録、命中音、火花を明示的に処理し、通常のヒットラグ処理への要求値も設定する。

コード本体は初回発動時にゲーム内ヒープへ確保し、独自の小さなLZストリームから展開する。
DCFlushRangeとICInvalidateRangeを実行してから使用する。ヒープの再作成前に参照を無効化し、
次の対戦で古い解放済みコードを再利用しない。コード一覧内に残す展開用コードと圧縮データを
含め、Dolphinの既定のGecko容量内に収めている。圧縮対象は生成したパッチのコードであり、
ゲームのアセットは含まない。

掴み判定にはゲーム内の判定生成、握りにはダメージ加算、投げには投げ処理を呼ぶ。
花はCHの握りごとにネイティブの花付与処理を呼び、継続ダメージの計算はゲーム側に任せる。
各手の拘束関係が失われた場合や相方が死亡・消滅した場合は解放して復帰する。

## 映像から確定できない部分

通常の映像には不可視の判定サイズ・座標・正確なノックバック値が映らない。
動画作者のコードは入手できていないため、それらの完全一致を確認したものではない。
v2では掴み判定をbone18の半径24相当へ拡張した（前版は残存値9.375相当）。
CHは通常掴みのローカル軸に従って鏡映した。拡張量は復元上の調整値であり、
動画作者の判定サイズを特定した値ではない。
投げのダメージとノックバック係数にはMHの残存連携投げ、CHの通常逆投げの値を使用する。
角度は両手とも270度とする。解放位置を手のbone18の下へ移し、衝突座標も更新する。
床との衝突はゲーム内の処理で判定し、接地後に衝撃演出を呼び、90度で上へ跳ね返す。
跳ね返りで追加の投げダメージは与えず、その後は通常のダメージ状態の衝突処理へ戻す。

受領したAJをDATのアニメーションオフセットから読み、両手とも掴み78、握り331、失敗100
フレームであることを確認した。bone18のX回転の指が閉じる側の極値は両手とも
49・78・107・136・165フレームにあり、握りはこの5箇所で発生する。
前版のactor tickによる仮のタイマーを廃止し、MHの実際のモーションフレームを基準にした。
v4の投げは、急な下降が始まった途中の212フレーム（下降区間210〜214）に設定した。この投げフレームは
モーションと映像からの復元上の判断であり、動画作者の発生フレームを確定した値ではない。
設定は `config/restoration.json` に分離している。

MHの握りはNormal属性0、CHはLipstick属性15を使用する。
前版のMHに指定したCatch属性8は通常のダメージ判定から除外されるため修正した。
音には通常掴みのDATに残るIDを使用し、掴み156、握り0x4E212と命中音113、投げ9、失敗225と、
ゲーム内のボスの笑い声関数を呼び出す。キャラクター音声の読み込み要求ではMH音声バンク32も指定する。

## 検証の範囲

生成したPowerPC命令をUnicorn PPC32で実行し、ゲーム関数の呼び出し先をモデル化して検証した。
2人の独立拘束、各手の5回攻撃と投げ、片側だけの掴み成功、両側空振り、相方死亡、
拘束相手の所有確認、4候補の選択、元のスタック上の移動座標、ABIのレジスタ保存を確認した。

v2ではさらに、提供されたDOLのPowerPC命令による判定・投げ・効果音コマンドの読み取りを
実行し、データがネイティブ処理で正しく解釈されることを確認した。
被ダメージ倍率・ワンパターン相殺等の周辺関数は等倍のモデルであり、衝突自体は実行していない。

これは完全なゲームエミュレーションではない。通常掴みの衝突解決、花の蓄積・継続ダメージ、
描画・実際の音声出力、Dolphin 5.0-21460上の修正版実行は未検証。
ゲーム本体・アニメーション・動画データはリポジトリに含めていない。
