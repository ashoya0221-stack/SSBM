# DAT・参考動画との照合と復元コード

## 受領したデータの照合

| ファイル | SHA-256 |
| --- | --- |
| PlMh.dat | `e563fb4b2d3d83758f976c11f85aa0898eb7dae1a7228b758b9d115312a371c9` |
| PlCh.dat | `26e4475f0e4f5f7b322bc96d652566e7737b5b9e90eceaac5c697997f2e45f60` |

提供された動画ファイルは約9.8秒。両手が別々のキャラクターを拘束し、
握り5回の後に投げる場面を確認した。
マスターハンド側は6%ずつ計30%、投げを含め42%になる。
クレイジーハンド側は最初の握りで7%になり、その後に1%ずつの継続ダメージも表示される。
これは通常掴みデータにも残るLipstick属性（花）と整合する。

復元の設定値はMH「6×5＋12」、CH「7×5＋16＋花」。
CHの直接ダメージは51%であり、継続ダメージを含む最終表示は経過時間にも依存する。
単に各握りを8%に設定したり、最終表示を58%に固定したりする実装にはしていない。

## 名前とアクションの対応

| 技名 | MH motion / action | CH motion / action |
| --- | --- | --- |
| Tagtsukamu | 339 / 385 | 334 / 380 |
| Tagnigiru | 340 / 386 | 335 / 381 |
| Tagshippai | 341 / 387 | 336 / 382 |
| Tagcancel | 342 / 388 | 337 / 383 |

上記はDAT内の名前と、提供されたDOLのアクション表を直接対応させたもの。
CHのaction385・386は死亡モーションであり、MHと同じ番号で開始してはいけない。

MHのTagtsukamuには46フレーム目からの掴み用判定が残る。
CHのTagtsukamuにはタイマーと判定消去しかなく、Tagnigiruにも握りの判定がない。
そのため、選択分岐への呼び出し追加だけでは完成しない。

## 実装

Gecko C2フックは3箇所。CHの連携候補選択、CHの未使用分岐、MHの未使用分岐を補う。
MHの開始コールバックから両手をそれぞれ正しいアクションへ遷移させる。
コールバック・スクリプトの参照はC2ペイロード内の現在位置から求める。
任意の空きRAMを決め打ちしてゲームのヒープと共有する方法は使っていない。

掴まれる側の初期化には、それぞれの手の通常掴みのコールバックを利用する。
各手が独立した `victim_gobj` を持ち、拘束が相互に対応しているかを確認する。
1回掴んだ手は掴み受付を閉じる。握り判定はその手の拘束相手だけを対象にする。
これにより最大2人を保持し、片方の空振りが他方の拘束を解かない構成にしている。

握り判定の生成と投げにはゲーム内の判定生成・投げ処理を呼ぶ。
花はCHの握りの属性として指定し、継続ダメージの計算はゲーム側に任せる。
各手の拘束関係が失われた場合や相方が死亡・消滅した場合は解放して復帰する。

## 映像から確定できない部分

通常の映像には不可視の判定サイズ・座標・正確なノックバック値が映らない。
動画作者のコードは入手できていないため、それらの完全一致を確認したものではない。
MHの残存判定（半径9.375、bone18）を基準にし、CHは通常掴みのローカル軸に従って鏡映した。
投げのノックバックにはMHの残存連携投げ、CHの通常逆投げの値を使用している。

握り発生は初期設定でactor tick 30・60・90・120・150、投げは210。
これは復元用の初期調整値であり、動画作者の発生フレームを確定した値ではない。
ヒットラグでは進行が止まるため、動画上の経過秒数とも直接は一致しない。
`config/restoration.json` に調整値を分離している。

## 検証の範囲

生成したPowerPC命令をUnicorn PPC32で実行し、ゲーム関数の呼び出し先をモデル化して検証した。
2人の独立拘束、各手の5回攻撃と投げ、片側だけの掴み成功、両側空振り、相方死亡、
拘束相手の所有確認、4候補の選択、元のスタック上の移動座標、ABIのレジスタ保存を確認した。

これは完全なゲームエミュレーションではない。通常掴みの衝突解決、花の蓄積・継続ダメージ、
実際のアニメーションと判定の一致、Dolphin 5.0-21460上のGeckoコード実行は未検証。
ゲーム本体・アニメーション・動画データはリポジトリに含めていない。
