# v4：握りダメージ・命中音・解放時期

US 1.00 / Dolphin 5.0-21460向け。2026年11月22日更新。

## 比較録画で判明した問題

提供された今回の録画と左右比較を確認した。v3ではMH側の握りが当たらず、CH側も
一部の回だけダメージが入っていた。従来のモデルテストは「保持された相手は手の判定と
重なる」と仮定していたため、この欠落を検出できなかった。

## 変更

- 保持枠の相手へ、US 1.00のダメージ加算関数 `0x8006CB20` を直接呼ぶ。
  MHは各回6%、CHは各回7%。空間上のヒットボックスは作らず、二重命中も防ぐ。
- 相手側の捕獲元を各回確認し、別の手の相手へ加算しない。握りでは保持枠を消さない。
- 命中の記録、火花、命中音113を明示的に呼ぶ。通常握りの動作音0x4E212も維持する。
  命中音113は提供DATのSFX設定をDOLの音声選択処理で解釈した値。
- キャラクター音声の読み込み要求にバンク32（`mhands.ssm`）を追加する。
  対戦中に他の音声バンクを停止・アンロードする処理は入れない。
- CHは花付与関数 `0x8007F9C4` を呼ぶ。US 1.00ではダメージを整数のr4で渡す。
- 被拘束者の被命中と両手の命中ヒットラグ要求を設定し、ゲーム本来の停止処理へ渡す。
- 解放を241から212フレームへ前倒し。AJの下降区間210〜214の途中で解放する。
  手の下への配置・下向きの投げ・床に接触した後の上向きの跳ね返りは維持する。

## 検証

提供DOLを指定した37項目のテストが成功。

- 空間上の衝突からダメージを加算しないモデルで、MHだけで2人、CHだけで2人、
  各手1人の保持を確認。各人5回の握り、保持の継続、2人分の投げを確認。
- 提供DOLの実命令でダメージ加算関数を実行し、6・12・18・24・30%、
  7・14・21・28・35%の増加と、各回のHUD更新呼び出しを確認。捕獲元も維持。
- 提供DOLの音声選択処理で、通常握りのSFX指定が命中音113になることを確認。
- 生成した音声要求フックからDOL本来の要求処理を実行し、キャラクター音声時に
  バンク32の読み込み要求が立ち、ほかの未指定キャラクターの要求が立たないことを確認。
- 211フレームでは投げを行わず、212フレームで両方を解放することを確認。
- v3から継続する中断時の解放、片手死亡、所有関係、コード展開・ヒープ再作成後の再展開も検証。

通常版3128バイト、確認版3104バイト。既定Gecko容量3256バイト以内。
コード本体と末尾の復帰処理はゲーム内ヒープに3516バイト確保して展開する。

## 確認の限界と導入

Dolphin上でのv4の描画・音声出力・実際の床衝突と、参考動画との完全一致は未確認。
HUDの検証は更新関数の呼び出しまでで、画面描画を実行したものではない。
命中エフェクト、花、ヒットラグ等の周辺処理にはモデル検証を含む。

旧コードを無効にしてv4だけを有効にし、ゲームを停止した状態からタイトルへ起動する。
音声読み込みも対戦準備時に行うため、旧ステートセーブを読み込まず新しい対戦を開始する。
同じ手に2人とも掴まれた場合、それぞれがその手のダメージを受ける。
MHの直接ダメージ合計は各人42%、CHは各人51%と花の継続ダメージ。
