# v2の修正と検証

US 1.00 / Dolphin 5.0-21460向け。2026年11月21日更新。

## 報告された症状に対する修正

| 症状・原因 | v2の変更 |
| --- | --- |
| 掴み範囲が狭い | bone18の掴み半径を9.375相当から24相当へ拡張 |
| 片方だけ失敗・待機へ戻る | MHが両手の段階を管理。両手が掴みモーションを終えてから同時に次へ進む |
| 握りと投げが各手の時計で進む | 2個の握り判定、2人分の投げをそれぞれ同じコールバック内で実行 |
| モーションと攻撃のタイマーが別 | AJ内の指の屈曲ピーク49・78・107・136・165を採用。MHの実モーションフレームを使用 |
| ヒットラグ等で姿勢がずれる | 2フレーム以上のずれをネイティブのアニメーション関数で補正 |
| MHの握りがCatch属性 | 通常ダメージ判定が処理するNormal属性へ修正。CHは花属性を維持 |
| 効果音がない | 通常掴み技の効果音IDとボスの笑い声関数を追加 |
| 中断時に残る拘束 | 所有関係を確認して解放。死亡した手を待機状態へ戻さない |

## 確認済み

- 提供DOL、PlMh.dat、PlCh.dat、両AJのハッシュを照合して生成。
- 両AJの掴み・握り・失敗の長さ78・331・100フレームと、共通の5回の屈曲ピークを確認。
- 生成したPowerPCコードをUnicornで実行し、独立した2人の保持、攻撃・投げの同時呼び出し、
  片側だけの成功、両側空振り、相方死亡・消滅、進行停止、呼び出し順の違いを検証。
- 提供DOLの判定デコーダを実行し、6/7ダメージ、Normal/花属性、拘束相手限定のフラグ、
  掴み属性、拡張半径を確認。投げデコーダで12/16ダメージとネイティブの角度を確認。
- DOLの効果音コマンドデコーダから、掴み音156・音量127・パン64で音声関数が呼ばれることを確認。
- DOLを指定したテストは29項目が成功。指定しない場合、DOLを使う4項目はスキップ。
- 通常版3024バイト、確認版3000バイト。既定Geckoコード領域の上限3256バイト以内。

## 未確認・推定が残る部分

Dolphinでの修正版の衝突・描画・音声出力・花の継続ダメージは未検証。
テスト中はゲーム関数のモデル、またはコマンドデコーダと周辺の等倍モデルを使用し、
実際の対戦を実行したものではない。

動画に映らない判定の形状・大きさ・座標や動画作者のコードは特定できない。
半径24と投げ241フレームは復元上の調整値であり、作者の値と一致すると確定したものではない。
各手の直接ダメージはMHが42%、CHが51%。CHの最終表示は花の継続時間で増える。

## 再現方法

```sh
python tools/build_gecko.py private/main.dol private/PlMh.dat private/PlCh.dat \
  --master-aj private/PlMhAJ.dat --crazy-aj private/PlChAJ.dat
SSBM_MAIN_DOL=private/main.dol python -m unittest discover -s tests -v
```

入力バイナリと映像はローカルに置き、リポジトリには追加しない。
