# 3P・4Pでの手動操作

US 1.00 / Dolphin 5.0-21460向け、v6起動方式を維持した捕獲追従統合版。

## 導入

GitHub Actionsで捕獲追従を含む試験用Geckoコードは生成済み。ただし、現在配布中の
`dist/Tagtsukamu-US-1.00-manual.txt` は従来のv6起動版であり、捕獲追従を含まない。
Dolphin実機確認が終わるまでは、その既存v6版を使用する。

3Pをマスターハンド、4PをクレイジーハンドのHuman操作に設定する。
確認対象は全員Human・チーム戦ONで、1P・2Pと3P・4Pの両手は別チーム。
Dolphinのコントローラーポート4に入力を割り当てる。

## コマンド

**4P クレイジーハンド：Y＋十字キー左。**

CHが所定位置へ移動すると、MHも自動で移動し、両手が揃って掴みを開始する。捕獲後はキャラクターモデルを手の骨へ接続し、ネームタグ用のPlayer座標も追従させる。
MHが別の技を実行中の場合は、その技が終わるのを待つ。MHが不在・死亡・休眠中なら中止する。
CHが他の技を実行中なら、通常待機へ戻ってから入力する。

v4・v5で案内した「続いて3PでY＋十字上」は不要。
他の三種類の連携技は、従来の4P側の要求と3PのY＋十字上を引き続き使用する。

## 変更と確認

v5はMHの未使用入力分岐 `0x80150320` へ接続していた。
v6はCHが移動完了後に呼ぶ待機初期化 `0x8015A114` へ接続し、
TagGrab要求ID380のときだけMHの移動と開始コールバックを登録する。
他の要求は元の待機初期化へ渡す。握りダメージ・音・解放・判定補完は従来どおり。

提供DOLのHuman用待機処理→4P入力→CH移動登録→CH到着コールバック→MH移動登録→
MH到着コールバック→両手の掴み初期化までを通して検証した。
3Pの入力をゼロにしたまま両手の初期化へ到達する。
既存検証を含め55項目成功。アニメーション読込・状態適用等は代替しており、
Dolphin上での全体動作は未確認。[検証範囲](manual-v6-validation.md)を参照。

通常版・確認版・手動版を同時に有効にしない。


## 捕獲追従の統合状況

この統合版は、動作確認済みのv6起動経路（CHの到着処理 `0x8015A114`）を維持し、旧版の `0x80150320` 人間入力フックへ戻さない。捕獲時のモデル接続とネームタグ座標同期を同じランタイムへ追加した。GitHub ActionsでPPCテスト39件が成功し、DOL本体を必要とする22件は入力ファイル未提供のためスキップ。試験用Geckoコードは407行・3256バイトで標準容量上限内に生成できた。ただし、実際のUS 1.00 DOLとの照合とDolphinでの捕獲モデル／ネームタグ追従は未確認なので、従来のv6配布コードは置き換えない。試験生成物は[PR #4のActions実行](https://github.com/ashoya0221-stack/SSBM/actions/runs/45932149417)から取得できる。
