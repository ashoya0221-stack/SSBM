# 3P・4Pでの手動操作

US 1.00 / Dolphin 5.0-21460向け、3P起動経路を復帰させた捕獲追従統合版（試験中）。

## 操作手順

1. 3Pをマスターハンド、4PをクレイジーハンドのHuman操作に設定する。
2. 1P・2Pを同じチーム、3P・4Pを反対チームにする。
3. Dolphinのコントローラーポート3・4にそれぞれ3P・4Pの入力を割り当てる。
4. ゲームを完全停止し、旧Tagtsukamuコードを無効にして、この統合版だけを有効にする。旧ステートは読み込まずタイトルから起動する。

## 発動操作

**1段階目：4P クレイジーハンドのY＋十字キー左（入力値 `0x0801`）。**

CHが移動して待機状態になるまで待ちます。US 1.00ではこの操作でCH側に要求380が登録されます。Y＋右（`0x0802`）では要求378になるため、代用できません。

**2段階目：3P マスターハンドのY＋十字キー上。**

MH側のHuman入力処理を起動し、CH側に残っている要求380を受けてMHの移動を登録します。両手の開始コールバックが揃ってから掴みを始めます。

**4Pだけで両手が自動起動するv6経路は、この統合版では使用しません。** 3P側の入力経路を使います。他の三種類の連携要求は変更せず、通常の入力処理へ渡します。なお、この統合版の実機動作はまだ確認できていません。

## 追従機能

捕獲時にキャラクターモデルを手の骨へ接続します。ネームタグ同期はネイティブのFighter accessory callback（Fighter+0x21AC）登録には依存させず、各手のtag_animが呼ばれるたびに、その手が保持する2枠の捕獲対象を走査します。対象ごとにネイティブのCAPTURE_FOLLOW（0x800DB018）でFighter座標を更新し、Player座標setter（0x800327A8）へ渡します。DOLのネイティブcallback dispatcher（0x8006D8A0）にはFighter+0x221Fのビット条件があるため、関数ポインタを登録しただけでは呼び出しを保証できません。今回の実機報告を受け、この条件付き経路を使わない毎フレーム同期方式へ変更しました。

今回の毎フレーム同期方式を含む統合版は、まだDolphin実機での再確認前です。現在配布中の `dist/Tagtsukamu-US-1.00-manual.txt` は従来のv6起動版で、今回の3P起動経路と捕獲追従を含みません。試験版の実機確認が済むまでは、配布用コードを置き換えません。

## 原因調査メモ

DOLのHuman側MH入力処理 `0x8014FF44` では、3PのY＋十字キー上（入力値 `0x0808`）を押している間、`0x8015BB10` でCHの要求値を読みます。要求値が380なら、`0x80150320` の分岐に到達します。この分岐に手動版フックを置いています。これはMH自身の要求フィールドを書き込む経路とは別です。別の入力分岐ではMH自身の要求380を設定し、`0x80153990` を呼んで状態373へ移しますが、今回の手動版はその経路を発動条件にしていません。

従来のv6統合ではCH到着フック `0x8015A114` からMHの移動登録を直接行っていました。今回の実機報告ではMHが動かなかったため、前回の仮説だけでは原因を解決できていません。さらに、前回の自動起動テストはP3に誤った入力値 `0x0801` を与えており、実際のY＋上分岐 `0x0808` を検証していませんでした。また、4P側についても入力値 `0x0801` は十字キー左であり、右（`0x0802`）では要求378になるため、要求380になりません。テストを修正しましたが、Dolphinでの動作確認までは成功と判断しません。
