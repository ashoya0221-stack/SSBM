# 3P・4Pでの手動操作

US 1.00 / Dolphin 5.0-21460向け、3P起動経路を復帰させた捕獲追従統合版（試験中）。

## 操作手順

1. 3Pをマスターハンド、4PをクレイジーハンドのHuman操作に設定する。
2. 1P・2Pを同じチーム、3P・4Pを反対チームにする。
3. Dolphinのコントローラーポート3・4にそれぞれ3P・4Pの入力を割り当てる。
4. ゲームを完全停止し、旧Tagtsukamuコードを無効にして、この統合版だけを有効にする。旧ステートは読み込まずタイトルから起動する。

## 発動操作

**1段階目：4P クレイジーハンドのY＋十字キー左。**

CHが移動して待機状態になるまで待ちます。US 1.00ではこの操作でCH側に要求380が登録されます。

**2段階目：3P マスターハンドのY＋十字キー上。**

MH側のHuman入力処理を起動し、CH側に残っている要求380を受けてMHの移動を登録します。両手の開始コールバックが揃ってから掴みを始めます。

**4Pだけで両手が自動起動するv6経路は、この統合版では使用しません。** 以前の実動作で確認された3P側の操作経路を使います。他の三種類の連携要求は変更せず、通常の入力処理へ渡します。

## 追従機能

捕獲時にキャラクターモデルを手の骨へ接続し、捕獲中のアクセサリーコールバックでPlayer座標を更新してネームタグも追従させます。

この統合版はまだDolphin実機での再確認前です。現在配布中の `dist/Tagtsukamu-US-1.00-manual.txt` は従来のv6起動版で、今回の3P起動経路と捕獲追従を含みません。試験版の実機確認が済むまでは、配布用コードを置き換えません。

## 原因調査メモ

DOLのHuman側MH入力処理 `0x8014FF44` は、CHの要求を `0x8015BB10` で読み、要求380のときに末尾の `0x80150320` 分岐を通ります。3PのY＋上入力ではMH自身の要求380も登録され、ネイティブ関数 `0x80153990` がMHを状態373へ移します。

一方、従来のv6統合ではCH到着フック `0x8015A114` からMHの移動登録を直接行い、3P側のHuman入力・状態373への遷移を通していませんでした。ユーザーの実機報告とこの差分が一致するため、今回の作業版では3P側フックへ戻しています。Dolphinで再確認するまでは、これを最終原因と断定しません。
