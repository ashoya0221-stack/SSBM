# 3P・4Pでの手動操作

US 1.00 / Dolphin 5.0-21460向け、v8手動版。

## 導入

ゲームを停止し、既存のTagtsukamuコードを全て無効にして、v8手動版のGeckoコード全体を新しいコードとして登録する。
有効にするTagtsukamuコードはv8手動版一つとし、旧ステートを使わずタイトルから起動する。

3P・4Pのプレイヤー枠にマスターハンドとクレイジーハンドを割り当て、両方をHuman操作にする。
通常の大乱闘（Versus）を使う。全員Human・チーム戦ONで、1P・2Pを同じチーム、3P・4Pの両手を反対チームにする。
Dolphinのコントローラーポート4に4Pの入力を割り当てる。

## コマンド

**4P クレイジーハンド：Y＋十字キー左。**

CHが所定位置へ移動すると、MHも自動で移動し、両手が揃って掴みを開始する。
MHが別の技を実行中の場合は、その技が終わるのを待つ。MHが不在・死亡・休眠中なら中止する。
CHが他の技を実行中なら、通常待機へ戻ってから入力する。

## v8の変更

v7ではP3をMH、P4をCHと固定していた。v8ではP3のプレイヤー実体を取得して、
そのファイター種別が要求した手と一致するかを確認する。一致しなければP4を調べる。
これにより、通常対戦でP3/P4の手の並びが逆になっていても、別の手へ技のアクション番号を渡さないようにする。

両手のTagtsukamuアクション番号（MH=385、CH=380）、モーション設定、掴み・握り・投げの本体は変更しない。
他の三種類の連携要求は元の待機処理へ渡す。

## 検証範囲と制限

起動テストにはP3=MH/P4=CHの通常配置に加え、P3=CH/P4=MHの逆配置を追加した。
逆配置でも要求種別に一致する手が選ばれ、MHが385、CHが380の状態で掴み初期化へ到達することを確認する。
P3が空でP4だけがCHの場合、CHをMHとして誤って開始しないことも確認する。

Player_GetEntityの戻り値はテスト内サービスで置き換えている。これはPowerPCコードの分岐と
プレイヤー種別チェックの検証であり、Dolphin上の通常大乱闘での動作確認ではない。
実際の対戦環境での確認は引き続き必要。
