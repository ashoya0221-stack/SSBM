# 3P・4Pでの手動操作

US 1.00 / Dolphin 5.0-21460向け、v7手動版。

## 導入

最初にリポジトリのv7修正を取り込み、ローカルのUS 1.00 main.dol と PlMh.dat、PlCh.dat から `python tools/build_gecko.py private/main.dol private/PlMh.dat private/PlCh.dat` を実行して手動版を再生成する。生成後、ゲームを停止し、既存のTagtsukamuコードを全て無効にして、
`dist/Tagtsukamu-US-1.00-manual.txt` の全内容を新しいGeckoコードへ登録する。
有効にするTagtsukamuコードはv7手動版一つとし、旧ステートを使わずタイトルから起動する。

3Pをマスターハンド、4PをクレイジーハンドのHuman操作に設定する。
通常の大乱闘（Versus）を使う。全員Human・チーム戦ONで、1P・2Pを同じチーム、3P・4Pの両手を反対チームにする。デバッグモードは使わない。
Dolphinのコントローラーポート4に入力を割り当てる。

## コマンド

**4P クレイジーハンド：Y＋十字キー左。**

CHが所定位置へ移動すると、MHも自動で移動し、両手が揃って掴みを開始する。
MHが別の技を実行中の場合は、その技が終わるのを待つ。MHが不在・死亡・休眠中なら中止する。
CHが他の技を実行中なら、通常待機へ戻ってから入力する。

v4〜v6で案内した「続いて3PでY＋十字上」は不要。P3/P4の取得はプレイヤースロットから行い、ボス用ファイター検索に依存しない。
他の三種類の連携技は、従来の4P側の要求と3PのY＋十字上を引き続き使用する。

## v7の変更と確認

v7は手動版の手検索を通常対戦のプレイヤースロット基準に変更した。P3の実体はPlayer_GetEntity(2)、P4の実体はPlayer_GetEntity(3)から取得し、デバッグ用のボスファイター検索に依存しない。
v6で追加したCHの移動完了後に呼ばれる待機初期化 `0x8015A114` の開始処理は維持し、
TagGrab要求ID380のときだけMHの移動と開始コールバックを登録する。
他の要求は元の待機初期化へ渡す。握りダメージ・音・解放・判定補完は従来どおり。

提供DOLのHuman用待機処理→4P入力→CH移動登録→CH到着コールバック→P3スロットからMH取得→MH移動登録→
MH到着コールバック→両手の掴み初期化までを通して検証した。
3Pの入力をゼロにしたまま両手の初期化へ到達する。
既存の55項目テストは、手検索のテスト前提を通常のP3/P4プレイヤースロット参照へ変更した。Player_GetEntityの実際のスロット内容はテスト側のサービスで置き換えており、アニメーション読込・状態適用等も代替している。Dolphin上の通常大乱闘での全体動作は未確認。[検証範囲](manual-v7-validation.md)を参照。

通常版・確認版・手動版を同時に有効にしない。
